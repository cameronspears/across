How Across works

Your file goes from your browser straight to theirs, encrypted the whole way. Our server only introduces the two browsers, and it never gets what it would need to read the file. Here’s exactly how, and how to check.

What happens when you send a file

  1. You pick a file. It stays on your device. Your browser makes a random secret and puts it in the link, after the #.
  2. Browsers never send the part after # to a website, so our server never sees the secret. It sees only a scrambled fingerprint of it (a SHA-256 hash), which it uses as a meeting-room name.
  3. When the other person opens the link, the two browsers swap three short setup messages through that room. These say how to reach each other, not what the file is.
  4. The browsers connect with WebRTC, the same technology video calls use. The connection is encrypted with keys made on the two devices.
  5. Before any file data moves, each browser proves it knows the secret, in a way tied to this exact encrypted connection. If anyone sat in the middle, including our server, the proofs wouldn’t match and the page would stop.
  6. The file streams straight into the receiver’s download. It is never uploaded to us or stored anywhere along the way.

The six-letter code

Instead of the link, the receiver can type a code like PZK MFS. Six letters are too few to be a secret on their own, so only the first two reach our server, to find the sender’s room. The other four never leave the two browsers. They’re checked with CPace, a standard method for proving you both know a short code without revealing it. Anyone without the code, our server included, gets one guess per try (about 1 in 130,000). After three wrong guesses, the sender’s page retires the code.

Hiding your IP address

Hide my IP address is on by default. Your browser then connects only through an encrypted relay run by Cloudflare, so the other person sees the relay’s address, not yours. The page also checks every setup message before sending it, and won’t send one that contains your address.

If you turn it off, the browsers connect directly, which is often faster but shows each of you the other’s IP address. To find its public address, your browser asks STUN servers run by Cloudflare and Google.

On the same Wi-Fi, the browsers also try a local connection using temporary .local names, so the file doesn’t leave your network. That reveals nothing outside it.

What we don’t do

  • No accounts, no ads, no analytics, no cookies, and no third-party scripts. The only thing the page saves on your device is your Hide my IP setting.
  • No file storage. There’s nowhere on our side to put one.
  • The page’s security policy (CSP) stops it loading code from anywhere else, or sending data to any website but this one. The only other outside connections are the WebRTC ones described above.

Check it yourself

Across is open source under the MIT license: github.com/cameronspears/across. The whole app is one file, public/index.html, plus a few small server functions. You can confirm the live site runs that exact file:

curl -s https://acrossfile.com/ | shasum -a 256

Compare the result with shasum -a 256 public/index.html in the repository. In your browser’s developer tools, the Network tab shows every request the page makes. You’ll see the setup messages and no file data.

What it can’t protect against

  • Anyone who gets the link or the code can download the file while your page is open. Share it like a password, and close the tab when you’re done.
  • Across can’t tell whether a file is safe. Only open files from people you trust.
  • A compromised device or browser extension on either end can see the file, as it could with any app.
